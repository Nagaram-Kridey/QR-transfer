# Physical benchmark protocol

**No real-device results are recorded yet.** Generated videos, synthetic QR images, browser tests and
simulator runs are software verification, not evidence of camera throughput on Android or iPhone.

## Before acceptance trials

1. Commit the tested code and record its commit ID. Use non-sensitive 10 KiB and 100 KiB fixtures
   generated by `tools/make_trial_payloads.py`; both ends verify the exact fixture hash.
2. Record Windows laptop/camera, Android phone and iPhone models, OS/browser versions and sender app.
3. Use the hosted HTTPS harness on phones. Camera access over a plain HTTP LAN URL is not supported.
4. Explore density/FPS/ECC/distance/lighting before acceptance, then freeze a complete settings cell.
   Start at 256-byte symbols, ECC M, 8 fps, steady devices, approximately 20–30 cm separation.
5. Prepare/load all runtime assets while online if necessary, then disable networking during transfer.
   The current page must remain open; this is not an installed-PWA/offline-cold-start test.

## One trial

- Start the sender first and let it loop. Enable the receiver preview and align the complete QR.
- Browser: press Start receiving. Python: press Space in the receiver window. This starts the timer.
- A successful trial completes reconstruction and SHA-256 verification before the timeout, without
  restarting the trial or changing settings. Saving time is excluded; acquisition and verification included.
- Timeout is max(60 seconds, 3 × original payload_KiB): 60 seconds at 10 KiB; 300 at 100 KiB.
- Export the local observation, then add device/settings/commit metadata to the CSV. Record every
  failed, timed-out or cancelled trial. Reset between trials. Do not remove failed runs from the denominator.
- User interruption after timing begins counts as cancelled, not an invisible retry. Abandoning setup
  before timing begins is not a trial. Backgrounding either device invalidates success; record a failure.

Use `trial-template.csv` as the header. The source column must be physical for field results. Keep
payload bytes and KiB distinct (1 KiB = 1024 bytes). Record relative direction explicitly. Never combine
opposite directions or different settings into one success percentage.

## Acceptance

20 trials per direction/settings cell. Tier A: ≥18/20 at 100 KiB and median successful rate ≥1 KiB/s.
Otherwise test Tier B: ≥18/20 at 10 KiB and ≥0.5 KiB/s. 16–17/20 or lower rate permits one eight-hour
tuning investigation and a new frozen run. <16/20 at 10 KiB, or failure after that investigation, stops
product expansion. Keep both old and new data. One pair clears initial feasibility; full v1 requires
both directions on Windows–Android and Windows–iPhone.

Report successes/20, failures by reason, median/p95 successful completion times and median original-file
KiB/s. Explicitly label successful-trial-only percentiles; retain timeout information alongside them.
18/20 is an observed proportion, not a guarantee of 90% population reliability. A supported 1 MiB
codec limit is not evidence for transferring 1 MiB through real cameras.

The CLI/browser reports are intentionally local and incomplete metadata records, not automatic gate
certificates. Commit raw trials and their settings before changing README/résumé claims.
